## 架构决策

### ADR-001: Multi-Agent 架构

**日期**: 2026-03-23
**状态**: 已采纳

**背景**:
需要一个能够处理日程和费用多个领域的系统。

**决策**:
采用 Multi-Agent 架构，Orchestrator + 领域 Agent。

**原因**:
- 各领域独立，便于维护
- 遵循单一职责原则
- 便于扩展新领域

---

### ADR-002: GLM-5 作为核心模型

**日期**: 2026-03-23
**状态**: 已采纳

**背景**:
需要选择一个大语言模型来驱动 Agent。

**决策**:
使用智谱 AI GLM-5。

**原因**:
- 中文理解能力优秀
- Function Calling 支持完善
- 成本相对较低
- 国内访问稳定

---

### ADR-003: Vercel AI SDK

**日期**: 2026-03-23
**状态**: 已采纳

**背景**:
需要一个 Agent 框架来管理工具调用和对话流程。

**决策**:
使用 Vercel AI SDK。

**原因**:
- 开箱即用
- 流式响应支持
- 工具调用抽象清晰
- 与 Next.js 深度集成

---

### ADR-004: PostgreSQL + Drizzle ORM

**日期**: 2026-03-23
**状态**: 已采纳

**背景**:
需要选择数据库和 ORM。

**决策**:
使用 PostgreSQL 配合 Drizzle ORM。

**原因**:
- PostgreSQL 成熟稳定
- 支持 pgvector（未来向量检索）
- Drizzle 轻量、类型安全
- 无需学习复杂 DSL
